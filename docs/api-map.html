前端 7 个函数 → 后端端点的映射

前端 (api/*.js)                    后端 (server.js)                  状态
───────────────────────────────────────────────────────────────────────────────

① fetchPoliciesByCompany()  ────▶ GET /api/app/policies             ✅ 通
     参数: hkid, company               └ 返回保单列表
     用途: 选保司后拉保单

② fetchHospitalsByPolicy()  ────▶ GET /api/app/policies/:id/hospitals  ✅ 通
     参数: policyNo                    └ 返回 Completed 合约医院
     用途: 看某保单覆盖哪些医院

③ issueQrToken()            ────▶ POST /api/app/qr/issue            ✅ 通
     参数: policy_id                  └ 返回 60s token
     用途: 生成动态 QR 码

④ refreshQrToken()          ────▶ 同上 (调 issueQrToken)            ✅ 通
     用途: 60s 到期换新 token

⑤ syncFromConsole()         ────▶ GET /api/app/sync                 ✅ 通
     参数: hkid                       └ 返回保单 + 医院统计
     用途: APP 前台轮询同步

⑥ fetchClaims()             ────▶ GET /api/app/claims               ✅ 通
     参数: hkid                       └ 返回理赔记录
     用途: 查看历史报销


⑦ verifyQrCode()            ────▶ POST /api/qr/verify               ❌ 断！
     参数: qrData, hospitalId   后端没有这个路由！
     用途: 医院扫码验证         仅 admin/qrcode/checkin 可用


⑧ verifyPolicy()            ────▶ (无 HTTP 请求)                    ❌ 假！
     用途: 患者 KYC 注册     纯前端 mock，setTimeout + 假 patient_id


⑨ sendChatMessage()         ────▶ POST /api/chat                    ⚠️ 半通
     参数: sessionId, query          └ 转发到 n8n :5678             n8n 没启动就 500
     用途: AI 咨询

对比后端已有的类似端点：
  POST /api/admin/qrcode/generate   ← 生成签到码（B端管理后台用）
  POST /api/admin/qrcode/checkin    ← 患者签到（B端管理后台用）
  GET  /api/admin/qrcode/history    ← 签到了历史（B端管理后台用）

差距：缺少给 APP 端的 /api/app/qr/verify（无需登录，医院扫码用）
