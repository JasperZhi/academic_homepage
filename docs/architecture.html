港人就医商保码 · 跨境医疗保险移动端
React Native 0.85.3 · 更新于 2026-06-16

1. 项目定位

HKEdgeApp 是「港人就医商保码」的 C 端移动应用，服务香港居民在大湾区（如中山陈星海医院）使用跨境医疗保险进行直接结算。用户完成身份验证 → 绑定香港保险公司保单 → 出示动态 QR 码给医院扫码 → 追踪理赔进度 → 申请退款。

后端对接 前海数据平台医院端中台（HKEdge_Management console）。

7. 核心业务流程

7.1 身份激活 → 绑定保司 → 出示医保码

sequenceDiagram
    actor User as 香港居民
    participant App as HKEdgeApp
    participant Console as 中台 :3000
    participant Hospital as 医院 HIS

    Note over User,App: Step 1: 身份验证
    User->>App: 打开 App, 点击"去激活"
    App->>User: RegistrationScreen
    User->>App: 输入姓名 + HKID + 手机号
    App->>App: 表单校验 (正则 HKID/手机)
    App->>User: login() → 跳转 Home

    Note over User,Console: Step 2: 绑定保险公司
    User->>App: 点击 Hero Card 选保司
    App->>User: 弹窗展示 9 家保司
    User->>App: 选择 AIA / ChinaLife / ...
    App->>Console: GET /api/app/policies?company=&hkid=
    Console-->>App: 返回保单列表
    App->>App: setPolicies() + 激活首张保单
    App->>User: Hero Card 变绿, 显示保司徽章 + 保单名

    Note over User,Hospital: Step 3: 出示医保码
    User->>App: 点击 "出示跨境医保码"
    App->>Console: POST /api/app/qr/issue
    Console-->>App: { token, exp: 60s }
    App->>User: QR 码 + 60s 倒计时
    App->>App: 每秒刷新倒计时, 到期自动换 token

    Note over Hospital,App: Step 4: 医院扫码结算
    Hospital->>Console: POST /api/hospital/scan {token, hospital_id}
    Console-->>Hospital: 患者 + 保单信息
    Hospital->>Hospital: 直接结算 (Direct Billing)

7.2 理赔追踪 → 退款

sequenceDiagram
    actor User as 用户
    participant App as HKEdgeApp
    participant Console as 中台

    User->>App: 打开 ClaimsList
    App->>Console: GET /api/app/claims?hkid=
    Console-->>App: 理赔列表
    App->>User: 理赔卡片 (医院/金额/状态/公式)

    alt 状态 = Settled (已结算)
        User->>App: 点击进入 ClaimDetails
        App->>User: 时间轴 + 费用明细
        User->>App: 点击 "申请退款"
        App->>App: 本地改状态 isRefunded=true
        App->>User: 退款已提交 → 1-3工作日到账
    else 状态 = Pending (处理中)
        App->>User: 显示审核进度
    else 状态 = Refunded (已退款)
        App->>User: 显示退款完成
    end

7.3 QR Token 生命周期

stateDiagram-v2
    [*] --> 请求Token: 进入 QRCodeScreen
    请求Token --> 签发成功: POST /api/app/qr/issue
    请求Token --> 本地降级: 中台不可用
    签发成功 --> 激活中: token + 60s TTL
    本地降级 --> 激活中: base64 本地生成
    激活中 --> 倒计时: 每秒 timeLeft--
    倒计时 --> 激活中: timeLeft > 0
    倒计时 --> 自动刷新: timeLeft = 0
    自动刷新 --> 请求Token: refreshQrToken()
    激活中 --> 手动刷新: 用户点击刷新
    手动刷新 --> 请求Token
    激活中 --> 切保单: 用户换保单
    切保单 --> 请求Token

15. 架构评审与改进方案

2026-06-16 Code Review · 9 条反馈逐条分析

15.1 统一服务层 — 解决后端系统暴露过多

现状问题：

CONSOLE_BASE_URL 硬编码在 4 个文件中，3 个 Screen 直接用裸 fetch() 绕过了 policyApi.js 的拦截器（无 Header 注入）：

screen/HomeScreen.js:17     ❌ const CONSOLE_BASE_URL = ...
screen/ClaimsListScreen.js:14 ❌ const CONSOLE_BASE_URL = ...
screen/QrScanScreen.js:18   ❌ const CONSOLE_BASE_URL = ...
api/policyApi.js:5          ✅ (唯一正确的位置)

改进方案： 将所有 HTTP 调用收敛到 api/ 目录，通过统一的 apiClient (Axios instance) 发起，禁止 Screen 直接 fetch。

graph LR
    subgraph "改造前 ❌"
        S1[HomeScreen] -- fetch --> B1[localhost:3000]
        S2[ClaimsListScreen] -- fetch --> B2[localhost:3000]
        S3[QrScanScreen] -- axios --> B3[localhost:3000]
        S4[policyApi.js] -- axios --> B4[localhost:3000]
    end

    subgraph "改造后 ✅"
        S5[所有 Screen] --> SVC[api/index.js<br/>统一 Service 层]
        SVC --> CLIENT[apiClient<br/>拦截器/缓存/降级]
        CLIENT --> BACKEND[localhost:3000]
    end

具体改动：
- 新建 api/index.js — 导出所有 API 函数
- 移走 HomeScreen、ClaimsListScreen、QrScanScreen 中的 fetch 调用
- CONSOLE_BASE_URL 只在 api/ 内定义一次

15.2 保障预览前置 — 激活前先展示覆盖信息

现状问题：

当前流程: 注册KYC → 选保司 → 拉保单 → 选保单 → 才知道能不能用
                     ↑ 用户在这里绑定了，才发现不适用

改进方案： 在选择保司的同时，立即展示保障预览卡片，让用户在绑定前就能看到关键信息。

sequenceDiagram
    actor User as 用户
    participant App as App
    participant API as 中台

    User->>App: 点击某保司（如 AIA）
    App->>API: 即时查询保障预览

    alt 可覆盖
        API-->>App: { status: eligible, hospitals: [陈星海,港大深圳], coverage: 500万, validUntil: 2027-01 }
        App->>User: 展示预览卡片 ✅<br/>"覆盖2家网络医院 · 保额500万HKD · 有效期至2027-01"
        User->>App: 确认绑定 → 再执行激活流程
    else 不覆盖
        API-->>App: { status: not_covered, reason: 该保司未接入跨境直赔网络 }
        App->>User: ⚠️ 不适用提示<br/>"该保司暂不支持大湾区直赔，请尝试其他保司"
        Note over User,App: 用户无需走注册流程，直接尝试下一个保司
    else 保单过期
        API-->>App: { status: expired, expiredAt: 2026-01 }
        App->>User: ⚠️ "保单已过期，请联系保险公司续保"
    end

具体改动：
- 新增 GET /api/app/coverage/preview?hkid=&company= 或 Mock 模拟
- HomeScreen 保司选择弹窗改为预览卡片 + 确认按钮两步交互
- 新增 CoveragePreviewCard 组件

15.3 会话缓存 — 减少重复 API 调用

现状问题： 每次切保司、进 QR 页面都重新请求，无任何缓存机制。

改进方案：

sequenceDiagram
    actor User
    participant Cache as Session Cache
    participant API as 中台

    User->>Cache: 首次查保单 (company=AIA)
    Cache->>API: GET /api/app/policies?company=AIA
    API-->>Cache: 保单列表 { ttl: 300s }
    Cache-->>User: 返回 + 缓存 5 分钟

    User->>Cache: 再次查保单 (company=AIA)
    Cache-->>User: 直接返回缓存 ✅ (不调 API)

    User->>Cache: 切换保司 (company=ChinaLife)
    Cache->>API: 新保司，无缓存 → 调 API
    API-->>Cache: 返回 + 缓存
    Cache-->>User: 返回

    User->>Cache: 5 分钟后再次查
    Cache->>Cache: TTL 过期，标记 stale
    Cache->>API: 重新请求
    API-->>Cache: 更新缓存

具体改动：
- api/ 层新增 CacheManager — 基于 key + TTL 的内存缓存
- 缓存 key：policies:${companyName}:${hkid}，TTL: 300s
- 缓存 key：qr:${policyNo}，TTL: 55s（略短于 token 实际 60s 有效期）
- 用户登出 → 清空全部缓存

15.4 QR 码鲁棒性 — 预生成 + 离线 + 保存

现状问题：
- 进 QR 页面才请求 → 医院排队时网络慢了就干等
- 网络失败只有 console.warn → 用户看到空白 QR
- 无预生成、无离线、无保存

改进方案：

stateDiagram-v2
    [*] --> 保单激活
    保单激活 --> 预生成QR: 立即后台生成 (不等用户打开)

    state 预生成QR {
        [*] --> 在线生成: POST /api/app/qr/issue
        在线生成 --> 缓存QR: 成功
        在线生成 --> 本地降级: 网络失败
        本地降级 --> 缓存QR: base64(token+hkid+ts)
        缓存QR --> 保存到本地: AsyncStorage
    }

    缓存QR --> QR就绪
    QR就绪 --> 打开QR页面: 用户点击 (瞬间渲染)
    打开QR页面 --> 展示QR: < 100ms 无 loading
    展示QR --> 到期刷新: 后台静默刷新
    到期刷新 --> 展示QR

    展示QR --> 保存相册: 用户长按/按钮
    展示QR --> 分享: 系统分享Sheet
    展示QR --> 截图提醒: 检测截图 → 提示"仅限当场使用"

具体改动：
- UserContext 新增 qrToken: { token, exp, policyNo } 状态
- 保单激活后立即异步调用 issueQrToken() 预生成
- QR Token 写入 AsyncStorage，离线时读取本地缓存
- QR 页面新增保存按钮 → react-native-share / 写入相册
- 加载态改为骨架屏，而非空白

15.5 身份验证自动化 — 医院扫码自验证

现状问题： RegistrationScreen 是纯客户端正则校验，verifyPolicy() 永远是 Mock。缺少后台身份交叉验证。

改进方案（需后端配合）：

医院 HIS 扫码 QR → 提取 { token, hkid_hash, timestamp }
  → POST /api/hospital/verify
    → 校验 token 有效期
    → 校验 hkid_hash 与保单绑定的 HKID 一致

App 端改动较小，主要是 QrScanScreen 的 payload 结构升级，增加 HKID hash 字段。

18.3 发现的 Bug 与修复

Bug 1: PolicyPickerModal 无法勾选保单

现象: 选 AIA 后弹出两个套餐（尊尚醫療 Premier / 基礎醫療 Basic），点击任意一行无反应，勾选图标不切换。

影响文件:
- screen/HomeScreen.js:95
- screen/QRCodeScreen.tsx:111

Bug 2: 切换保险公司后 Hero Card 仍显示旧保司名

现象: 已绑 AIA 的用户点击保司徽章切换为 Prudential，保单列表正确更新为 Prudential 的保单，但 Hero Card 徽章仍显示 "AIA Hong Kong (友邦)"。

根因: VALID_TRANSITIONS 缺少 ACTIVATED → PREVIEWING 转移。bindInsurer() 尝试从 ACTIVATED 跳到 PREVIEWING 被状态机拦截返回 false，selectedInsurer 未更新。但后面的 activatePolicies() 没有检查返回值照常执行（ACTIVATED → ACTIVATED 是合法的），导致「policies 换了但公司名没换」。

修复:
- VALID_TRANSITIONS 补了 ACTIVATED → PREVIEWING、QR_READY → PREVIEWING、TOKEN_EXPIRING → PREVIEWING
- handleBindCompany 加了 bindInsurer 返回值校验，失败直接 return

影响文件:

- screen/HomeScreen.js — 防御检查
