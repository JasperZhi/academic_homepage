HK Medical Insurance Code for HK Residents · Cross-border Medical Insurance Mobile App
React Native 0.85.3 · Updated 2026-06-16

1. Project Positioning

HKEdgeApp is the consumer-side mobile app of the "HK Medical Insurance Code for HK Residents" project, serving Hong Kong residents who use cross-border medical insurance for direct billing in the Greater Bay Area (e.g., Chen Xinghai Hospital in Zhongshan). The user flow: identity verification → binding a Hong Kong insurance company policy → presenting a dynamic QR code to the hospital for scanning → tracking claim progress → requesting refunds.

The backend is the Qianhai Data Platform Hospital-side Middleware (HKEdge_Management console).

15. Architecture Review and Improvement Plan

2026-06-16 Code Review · item-by-item analysis of 9 feedback items

15.1 Unified Service Layer — Resolving Excessive Backend Exposure

Current problem:

CONSOLE_BASE_URL is hardcoded in 4 files, and 3 screens use raw fetch(), bypassing the interceptors in policyApi.js (no header injection):

screen/HomeScreen.js:17     ❌ const CONSOLE_BASE_URL = ...
screen/ClaimsListScreen.js:14 ❌ const CONSOLE_BASE_URL = ...
screen/QrScanScreen.js:18   ❌ const CONSOLE_BASE_URL = ...
api/policyApi.js:5          ✅ (the only correct location)

Improvement: Consolidate all HTTP calls into the api/ directory, issued through a unified apiClient (Axios instance); screens are prohibited from fetching directly.

graph LR
    subgraph "Before ❌"
        S1[HomeScreen] -- fetch --> B1[localhost:3000]
        S2[ClaimsListScreen] -- fetch --> B2[localhost:3000]
        S3[QrScanScreen] -- axios --> B3[localhost:3000]
        S4[policyApi.js] -- axios --> B4[localhost:3000]
    end

    subgraph "After ✅"
        S5[All screens] --> SVC[api/index.js<br/>unified service layer]
        SVC --> CLIENT[apiClient<br/>interceptors/cache/fallback]
        CLIENT --> BACKEND[localhost:3000]
    end

Specific changes:
- Create api/index.js — export all API functions
- Move fetch calls out of HomeScreen, ClaimsListScreen, QrScanScreen
- CONSOLE_BASE_URL defined only once, inside api/

Current flow: KYC registration → select insurer → fetch policies → select policy → only then know if usable

15.3 Session Cache — Reduce Redundant API Calls

Current problem: Every insurer switch and every visit to the QR screen triggers a new request; there is no caching mechanism.

Improvement:

sequenceDiagram
    actor User
    participant Cache as Session Cache
    participant API as Middleware

    User->>Cache: First policy query (company=AIA)
    Cache->>API: GET /api/app/policies?company=AIA
    API-->>Cache: Policy list { ttl: 300s }
    Cache-->>User: Return + cache for 5 minutes

    User->>Cache: Query policies again (company=AIA)
    Cache-->>User: Return from cache directly ✅ (no API call)

    User->>Cache: Switch insurer (company=ChinaLife)
    Cache->>API: New insurer, no cache → call API
    API-->>Cache: Return + cache
    Cache-->>User: Return

    User->>Cache: Query again after 5 minutes
    Cache->>Cache: TTL expired, mark stale
    Cache->>API: Request again
    API-->>Cache: Update cache

Specific changes:
- Add a CacheManager in the api/ layer — in-memory cache based on key + TTL
- Cache key: policies:${companyName}:${hkid}, TTL: 300s
- Cache key: qr:${policyNo}, TTL: 55s (slightly shorter than the token's actual 60s validity)
- On user logout → clear all cache

15.4 QR Code Robustness — Pre-generate + Offline + Save

Current problem:
- Request is made only upon entering the QR screen → user waits idle when the network is slow while queuing at a hospital
- Network failure only triggers console.warn → user sees a blank QR
- No pre-generation, no offline support, no saving

Improvement:

stateDiagram-v2

    PolicyActivated --> PreGenerateQR: generate in background immediately (do not wait for user to open)

    state PreGenerateQR {
        [*] --> OnlineGeneration: POST /api/app/qr/issue
        OnlineGeneration --> CacheQR: success
        OnlineGeneration --> LocalFallback: network failure
        LocalFallback --> CacheQR: base64(token+hkid+ts)
        CacheQR --> SaveLocally: AsyncStorage
    }

    CacheQR --> QRReady
    QRReady --> OpenQRScreen: user taps (instant render)
    OpenQRScreen --> ShowQR: < 100ms, no loading
    ShowQR --> RefreshOnExpiry: silent background refresh
    RefreshOnExpiry --> ShowQR

    ShowQR --> SaveToGallery: user long-press/tap
    ShowQR --> Share: system share sheet
    ShowQR --> ScreenshotWarning: detect screenshot → prompt "for on-site use only"

Specific changes:
- Add qrToken: { token, exp, policyNo } state to UserContext
- Call issueQrToken() asynchronously immediately after policy activation to pre-generate
- Write QR token to AsyncStorage; read local cache when offline
- Add a save button on the QR screen → react-native-share / write to gallery
- Replace the blank loading state with a skeleton screen

15.5 Identity Verification Automation — Hospital Scan Self-Verification

Current problem: RegistrationScreen is purely client-side regex validation; verifyPolicy() is always a Mock. There is no backend cross-validation of identity.

Improvement (requires backend support):

Hospital HIS scans QR → extract { token, hkid_hash, timestamp }
  → POST /api/hospital/verify
    → Validate token validity period
    → Validate hkid_hash matches the HKID bound to the policy
    → Validate timestamp is within a reasonable window (±5min anti-replay)
    → Return { patient_name, policy_status, coverage }

App-side changes are small, mainly upgrading the QrScanScreen payload structure to include an HKID hash field.

15.6 Add Missing Error Paths

Current problem: The architecture document and code cover only the happy path. Actual scenarios:

Error Scenario Current Handling Required Handling
Policy expired No check Mark expired in UI + refuse to generate QR
Insurer not covered No prompt Intercept at preview stage
Network timeout console.warn Toast + retry button
Identity mismatch No check Backend validation + frontend blocking
Token stolen Undetected Anomalous login detection + refresh

The improved state machine includes all error branches:

stateDiagram-v2
    [*] --> UNVERIFIED
    UNVERIFIED --> VERIFIED: KYC success
    UNVERIFIED --> UNVERIFIED: KYC failure / format error

    VERIFIED --> INSURANCE_PREVIEW: query insurer coverage
    INSURANCE_PREVIEW --> POLICY_ACTIVE: covered ✅ user confirms binding
    INSURANCE_PREVIEW --> INSURANCE_PREVIEW: not covered ⚠️ switch insurer
    INSURANCE_PREVIEW --> VERIFIED: policy expired ❌

    POLICY_ACTIVE --> QR_READY: pre-generate QR
    QR_READY --> TOKEN_EXPIRED: 60s expiry
    TOKEN_EXPIRED --> QR_READY: refresh success
    TOKEN_EXPIRED --> QR_ERROR: refresh failure (network)
    QR_ERROR --> QR_READY: retry success

    POLICY_ACTIVE --> POLICY_EXPIRED: insurer pushes expiry notice
    POLICY_EXPIRED --> INSURANCE_PREVIEW: reselect insurer

15.7 Settlement Flow Optimization — Direct Billing First

Current problem: The formula shown in ClaimsListScreen, Total - Covered = You Pay, resembles a reimbursement model.

Improvement: In the QR direct-billing scenario, the settlement flow becomes:

Treatment completed → hospital submits settlement request → middleware computes covered amount in real time → user pays only the difference

App-side changes:
- Add SettlementScreen — display instant settlement results (direct-billed amount + out-of-pocket amount)
- ClaimsListScreen distinguishes two card types: "direct billing" and "traditional claim"
- Direct billing card shows: Total - DirectBilling = YouPay (reduces user anxiety)

15.9 Event-Driven → State-Driven

Current problem: Business logic is pieced together from scattered booleans; state transitions are implicitly scattered across screens.

18.3 Bugs Found and Fixes

Bug 1: PolicyPickerModal cannot select a policy

Symptom: After selecting AIA, two plans appear (尊尚醫療 Premier / 基礎醫療 Basic); tapping any row has no effect and the checkmark icon does not toggle.

Root cause: The handlePickPolicy handlers in HomeScreen.js and QRCodeScreen.tsx called setActivePolicy(policy.id), passing a string (e.g., "p_aia_001"), but setActivePolicy expects a full policy object. This made activePolicy a string, so .id / .policyNo / .planName were all undefined. PolicyPickerModal's isActive check item.id === activePolicyId never matched.

Fix: Changed both setActivePolicy(policy.id) → setActivePolicy(policy).

Affected files:
- screen/HomeScreen.js:95
- screen/QRCodeScreen.tsx:111

Bug 2: Hero Card still shows the old insurer name after switching insurers

Symptom: A user bound to AIA taps the insurer badge to switch to Prudential; the policy list correctly updates to Prudential's policies, but the Hero Card badge still shows "AIA Hong Kong (友邦)".

Root cause: VALID_TRANSITIONS was missing the ACTIVATED → PREVIEWING transition. bindInsurer()'s attempt to jump from ACTIVATED to PREVIEWING was blocked by the state machine and returned false, so selectedInsurer was not updated. But the subsequent activatePolicies() did not check the return value and proceeded anyway (ACTIVATED → ACTIVATED is a valid transition), resulting in "policies changed but company name did not".

Fix:
- Added ACTIVATED → PREVIEWING, QR_READY → PREVIEWING, and TOKEN_EXPIRING → PREVIEWING to VALID_TRANSITIONS
- Added a return-value check for bindInsurer in handleBindCompany, returning early on failure

Affected files:
- context/UserContext.js — valid transition table
- screen/HomeScreen.js — defensive check

Bug 3: iOS build failure — AppIcon missing

Symptom: xcodebuild reported None of the input catalogs contained a matching stickers icon set, app icon set, or icon stack named "AppIcon".

Root cause: project.pbxproj contained ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon, but Images.xcassets had no AppIcon.appiconset.

Fix: Removed the ASSETCATALOG_COMPILER_APPICON_NAME configuration lines from both the Debug and Release configurations.

15.3 会话缓存 — 减少重复 API 调用

现状问题： 每次切保司、进 QR 页面都重新请求，无任何缓存机制。

改进方案：

sequenceDiagram
    actor User
    participant Cache as Session Cache
    participant API as 中台

    User->>Cache: 首次查保单 (company=AIA)
    Cache->>API: GET /api/app/policies?company=AIA
    API-->>Cache: 保单列表 { ttl: 300s }
    Cache-->>User: 返回 + 缓存 5 分钟

合法状态转移

GUEST       → VERIFIED        (KYC 成功)
GUEST       → GUEST           (浏览首页)

VERIFIED    → PREVIEWING      (查看保司覆盖)
VERIFIED    → GUEST           (登出)

PREVIEWING  → ACTIVATED       (确认绑定)
PREVIEWING  → VERIFIED        (不适用/过期/取消)

ACTIVATED   → QR_READY        (预生成 QR 成功)
ACTIVATED   → PREVIEWING      (切换保司)
ACTIVATED   → ACTIVATED       (切换保单)
ACTIVATED   → VERIFIED        (解绑保司)
ACTIVATED   → POLICY_EXPIRED  (保单过期通知)
ACTIVATED   → GUEST           (登出)

QR_READY    → TOKEN_EXPIRING  (倒计时到 10s)
QR_READY    → PREVIEWING      (切换保司)
TOKEN_EXPIRING → QR_READY     (刷新成功)
TOKEN_EXPIRING → ACTIVATED    (刷新失败，需手动重试)
TOKEN_EXPIRING → PREVIEWING   (切换保司)

POLICY_EXPIRED → PREVIEWING   (重新选择保司)
POLICY_EXPIRED → GUEST        (登出)

18.3 发现的 Bug 与修复

Bug 1: PolicyPickerModal 无法勾选保单

现象: 选 AIA 后弹出两个套餐（尊尚醫療 Premier / 基礎醫療 Basic），点击任意一行无反应，勾选图标不切换。

根因: HomeScreen.js 和 QRCodeScreen.tsx 的 handlePickPolicy 调用了 setActivePolicy(policy.id)，传入的是字符串（如 "p_aia_001"），但 setActivePolicy 期望完整 policy 对象。导致 activePolicy 变成字符串，.id / .policyNo / .planName 全部为 undefined。PolicyPickerModal 的 isActive 判断 item.id === activePolicyId 永远不匹配。

修复: 两处 setActivePolicy(policy.id) → setActivePolicy(policy)。

影响文件:
- screen/HomeScreen.js:95
- screen/QRCodeScreen.tsx:111

Bug 2: 切换保险公司后 Hero Card 仍显示旧保司名

现象: 已绑 AIA 的用户点击保司徽章切换为 Prudential，保单列表正确更新为 Prudential 的保单，但 Hero Card 徽章仍显示 "AIA Hong Kong (友邦)"。

根因: VALID_TRANSITIONS 缺少 ACTIVATED → PREVIEWING 转移。bindInsurer() 尝试从 ACTIVATED 跳到 PREVIEWING 被状态机拦截返回 false，selectedInsurer 未更新。但后面的 activatePolicies() 没有检查返回值照常执行（ACTIVATED → ACTIVATED 是合法的），导致「policies 换了但公司名没换」。

修复:
- VALID_TRANSITIONS 补了 ACTIVATED → PREVIEWING、QR_READY → PREVIEWING、TOKEN_EXPIRING → PREVIEWING
- handleBindCompany 加了 bindInsurer 返回值校验，失败直接 return

影响文件:

- screen/HomeScreen.js — 防御检查
